0.17.1 · Use existing folders directly

Build 36 · local alpha candidate · 11 September 2026

Not yet published. The public download remains version 0.16.0.

0.15.0 · Video keywords

Build 32 · Local alpha candidate · Not yet released

0.14.0 · Monthly archive folders

Build 31 · Local alpha candidate · Not yet released

  • New archives: Fixed layout under YYYY/YYYY-MM/YYYY-MM-DD, such as 2026/2026-09/2026-09-10. Only months and days containing files are created; folder names remain complete. Unbekannt stays directly in the chosen archive, without an extra media folder.
  • Explicitly migrate existing day folders: “Review folder structure…” creates a preview first. Only “Switch to monthly folders” followed by confirmation starts the migration. Opening the archive and later imports do not change its existing layout.
  • Keep pairs and relationships: Archive media move together with their XMP files; identities, origins, variants and metadata are preserved. Nothing is copied from the sources again. After an interruption, “Resume migration” checks the existing evidence before continuing.
  • Very old media archives: The layout under Medien/YYYY/YYYY-MM-DD remains supported. This monthly migration is not offered for it.

Before migration, make an independent backup of the archive including XMP and pause other programs that write to it. Afterwards, digiKam and other existing libraries may need a new scan or their folder links updated. Older TrueArchive versions cannot read or continue using the monthly layout; use at least 0.14.0 on all Macs working with it.

This entry describes the local candidate, not a published release or completed release validation. The public package remains 0.13.1; the shared automatic update feed stays unchanged. It does not establish migration of personal archives or real Intel/Nitro/digiKam acceptance testing.

0.10.0 · Duplicates and Nitro variants

9 September 2026 · Build 18 · Alpha

Note added on 9 September: With an active menu bar display, this version may freeze and use a large amount of memory. We recommend that new testers wait for an invitation with a corrected, verified version.

  • Identical media from multiple sources: After a full byte check and compatibility check of the metadata, the same archive file is reused. Its XMP contains all origins. This also applies to local pictures and matching resources from Apple Photos.
  • Keep Nitro edits: Different readable recipes automatically get their own media/XMP pairs when the remaining metadata is compatible. Identical recipes are recognized. Other conflicts can be imported separately in the preview with “Keep both versions” or left unresolved for later.
  • Check existing duplicates: The archive page offers an explicitly started read-only scan with progress, pause and cancellation. It distinguishes identical copies, edit variants and hard links; it does not delete or merge archive files.
  • Help next to the feature: “?” buttons open the relevant handbook chapter. The Help menu also links to the handbook and release notes. Operating instructions and version history are maintained with each release.
  • Activity in the menu bar: Small rotating arrows show ongoing work. Idle, pause and issue states stay still; the macOS “Reduce Motion” setting is respected. The status window has a clear cancel button for a full sync.
  • Protecting performance: Fixed synthetic performance tests compare importing, repeat runs and shared origins against a matching reference for the machine. Runtime and memory limits will be part of release checks going forward.

Mind the archive format: Once new shared origin or variant data is written, the archive receives format protection 6. Use at least TrueArchive 0.10.0 on every Mac afterwards. Older apps refuse to write. Existing folders are not reorganized; media and XMPs remain ordinary files.

A confirmed new origin counts as a metadata change; a separate variant counts as a new file. The amount of copying avoided does not measure freed disk space. Sources remain unchanged.

With the additional origin checks, Photos sync is slower in developer testing than in 0.9. The new performance suite establishes a reference for the current functionality; further optimization is pending.

For macOS 15+, Intel and Apple Silicon. Still not notarized by Apple. Actual Intel runtime checks, real iCloud imports and round-trip tests with Nitro and digiKam remain separately pending for this release. RAW/JPEG matching and searching for pictures that only look similar are not included.

0.8.0 · Unlimited Photos sync

9 September 2026 · Build 15 · Alpha

Apple Photos gets a direct sync without an overall item limit and an optional, persistently saved capture date range.

  • Entire accessible library: “Archive all items” processes all accessible pictures and videos. Technical processing remains limited to at most 20 items per checked batch.
  • Inclusive capture date range: “From” and “To” can be set together or individually; both selected calendar dates are included. With the filter active, items with no known capture date are skipped. Without a filter, there is no date restriction.
  • One range for every sync: The saved capture date range applies to direct and explicitly enabled scheduled Photos syncs. Changing the range does not enable a schedule.
  • Setup in three steps: Choose sources, choose an archive and finish. The earlier ten-picture trial is removed; start the first sync afterwards on the source page.

Downgrade note: The alpha saves local setup as schema 2. TrueArchive 0.7.x rejects these new settings so a date filter cannot be silently lost. This does not change the archive format or already archived files.

For macOS 15 or later, Intel and Apple Silicon. The alpha package is ad hoc signed and not notarized by Apple. Real runtime acceptance on Intel and complete real iCloud imports are still pending.

0.7.0 · Keep previews, choose destinations clearly

9 September 2026 · Build 13 · Beta

Sources, the archive destination and ongoing work are easier to distinguish. You can browse the app and then continue working with your selection.

A clearer workspace

  • Previews are preserved: Switching to the archive destination or another source no longer discards a checked selection. Each local source retains its own preview and selection during the current app session.
  • You control navigation: Automatic syncs no longer open a different source page. A fixed status area shows ongoing work; “Go to operation” takes you straight there. Results belong to the source actually processed.
  • Settings in one place: Each source has “Settings …” for its configuration and schedule. The archive destination shows connection, folder and free space first; local keywords have their own settings.
  • Clear completion: After importing, the result and “Open archive” take priority. “Remove source from List …” explicitly refers to removing the connection; files are preserved.

Switch archive destinations reliably

A selected destination folder is checked before becoming the active archive. If selection fails, the app shows “Destination change still pending” and blocks further imports. It does not silently return to the previous archive, even after a restart. Select the intended destination again and check the displayed folder.

Changing the archive discards old previews. If a source’s scope changes, its preview becomes invalid. Still-valid previews for other sources remain and continue to prevent automatic imports, keyword tagging and app updates in the background.

Sync Apple Photos once

  • “Sync Library”: imports the entire accessible System Photo Library, including videos, in batches of at most 20 items. Progress and results count across the entire run. Existing schedules and their pause remain unchanged.
  • “Select Latest”: still creates a limited preview for an explicit selection. Before a library sync, open previews must be archived or discarded.
  • The one-time sync can be cancelled and stops on an incomplete batch or an error. Already archived files are preserved; another deliberate start recognizes them. Photos and videos are not deleted from Apple Photos.

Updates and testing status

From 0.6.0, the existing app updater can obtain this release once ongoing work and open previews are finished. Coming from 0.5.0 or earlier still requires a manual installation. After launch, check the destination folder on the archive page before starting a real import.

For macOS 15 or later; the pilot is still not notarized by Apple. Intel runtime acceptance, complete native interaction checks and real imports from external drives and iCloud are still pending for this version. The accessible System Photo Library is not independent proof of all iCloud content.

0.6.0 · The app keeps itself up to date

9 September 2026 · Build 12 · Beta

TrueArchive can download and install new app versions itself. Running and paused archive work takes priority.

New

  • Automatic app updates: enabled by default. TrueArchive checks roughly once a day while the app is running and the Mac is awake. Installation takes place when idle, followed by a restart.
  • Manual mode: automatic updates can be turned off under “TrueArchive → Settings → App updates”. Your choice stays saved.
  • Check for updates yourself: through the app menu or settings. In the menu bar window, “App updates …” goes directly to the setting.
  • Verified origin: The update feed and app packages are digitally signed and verified before installation.

Protecting ongoing work

  • Checking, copying, paused imports, Photos export, recovery and local keyword tagging prevent updates and quitting the app.
  • An unfinished setup or open import preview prevents an automatic restart. No new archive jobs start during an update.

Before updating

Coming from 0.5.0 or earlier: Install 0.6.0 manually once. Only then can TrueArchive obtain further versions itself. Finish running archive work and close the older app first.

Changing automatic updates in the update dialog applies to future updates; it does not cancel an update already prepared.

For macOS 15 or later, as one package for Intel and Apple Silicon. The pilot is still not notarized by Apple. Intel runtime testing for this version and full interaction checks of the update interface are still pending.
